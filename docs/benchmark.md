## Real-world PDF (MS Word export)

`tests/benchmark_realworld.py` downloads the Arabic UDHR PDF (Aalto University
UDHR corpus copy of the UN text, made with Microsoft Word). There is no exact
ground truth, so the metric is the share of extracted Arabic words found in the
reference vocabulary. A reversed or split word falls outside it. The reference
text was itself made with pdftotext, which favours that tool. Most of Waraq's
remaining "misses" are tanween spellings where the reference is the odd one out.

| tool | Arabic words | in reference vocabulary |
|---|---|---|
| Waraq | 1317 | 98.4% |
| pypdf | 1315 | 96.0% |
| pdfminer.six | 1330 | 4.4% |
| pdftotext | 1306 | 99.5% |

A second real file, the official UN UDHR PDF, uses a broken font encoding.
On it every tool loses words, measured by the same vocabulary method: Waraq 71.8%,
pdftotext 62.9%, pypdf 58.9%, pdfminer 10.4%. Such files need OCR ("Force OCR"
option). Waraq does **not** yet detect garbage text layers automatically.

camera photos would. Expect smaller savings on real scans. If the result would
be larger than the input, the original is kept.

## OCR (Tesseract 5, ara+eng, synthetic 200-dpi scan)

CER 0.096–0.129 per page, about 1.4 s per page. Arabic words are correct. Short Latin or number
runs inside Arabic lines are sometimes placed in the wrong order (e.g. "11 Windows",
the phone number). Windows built-in OCR could not be tested on Linux.
